Chapter 3 · Transformers

Transformers, one piece at a time.

We already know what a neural network is and how it learns. Now we will follow one piece of text through a transformer and ask what every new operation is actually doing.

Builds on Chapters 1–2~35–40 min read3 interactive demosNo vocabulary jump

The easiest way to get lost in transformers is to meet tokens, embeddings, queries, keys, values, attention heads, logits, softmax, and MLPs all at once. We will not do that. Each term will appear only when we have a reason to need it.

text→tokens→vectors→context→attention→MLP→next token

1. What exactly is a transformer?

A transformer is a special kind of neural network.

That connection matters. We are not leaving Chapter 1 behind. Transformers still contain learned weight matrices, nonlinear functions, forward passes, loss, gradients, and backpropagation.

Then what makes a transformer special?

Its architecture. In particular, transformers contain a mechanism called attention that lets the vector for one token be updated using information from other tokens in the context.

For the kind of transformer used in a GPT-style language model, the goal is simple to state:

Given some text, produce a probability distribution for what token could come next.

The name GPT stands for:

Generative

It generates new text.

Pre-trained

It is trained on a very large amount of data before we use it.

Transformer

The neural-network architecture doing the computation.

2. First problem: the transformer cannot read raw English

Suppose the input begins with:

To date, the cleverest thinker of all time was ...

The model does not send that sentence into the network as one piece. It first breaks the text into smaller chunks called tokens.

To date, the cleverest thinker of all time was
Is a token always a whole word?

No. A token can be a word, part of a word, punctuation, or another text chunk. The important point is that the model works with a fixed vocabulary of tokens.

Each token has an ID, but the ID is only a label. The model still needs a much richer numerical representation.

3. Tokens become vectors called embeddings

Each token is associated with a long list of numbers. That list is called an embedding.

token  →  [number, number, number, ...]  →  embedding

It is useful to imagine that list of numbers as coordinates in a very high-dimensional space.

For GPT-3, the embedding dimension used in this running example is 12,288. So one token is represented by a vector containing 12,288 numbers.

Why so many numbers?

The space needs many directions so the model has room to represent many different kinds of meaning. During training, the embedding matrix is adjusted along with the rest of the model's parameters.

One important idea is that directions in embedding space can correspond to aspects of meaning. This does not mean that one coordinate cleanly means one human concept. The useful information can be spread across many dimensions.

Keep this mental picture: a token starts as a point in a huge vector space. As it passes through the transformer, its vector gets changed so that it can hold more and more context.

4. One mathematical tool we need: the dot product

Before attention, we need one piece of vector math.

The dot product gives us a number that tells us how well two vectors align.

a · b = a₁b₁ + a₂b₂ + ...
What does “align” mean here?

If two vectors point in similar directions, their dot product is positive and can be large. If they are perpendicular, the dot product is zero. If they point in opposite directions, the dot product is negative.

This will become the central comparison operation inside attention.

5. Before attention: what does the whole transformer look like?

At a high level, the token vectors pass through two kinds of blocks again and again:

token embeddings
↓
attention
↓
MLP / feed-forward
↓
repeat attention + MLP many times
↓
next-token probabilities

Inside an attention block, the token vectors can affect one another.

Inside an MLP block, each token vector is processed independently by the same neural-network operation.

Why alternate these two operations?

Attention lets a vector absorb useful context from other positions. The MLP then transforms each vector further. Repeating the two operations gives the model many chances to build richer representations.

Now we can zoom in on attention.

Consider the word mole in three different phrases:

So when does the meaning become context-specific?

Inside the transformer. The attention block gives surrounding token embeddings a chance to influence and update the embedding for mole.

Attention needs a way to answer two separate questions:

  1. Which other tokens are relevant?
  2. If a token is relevant, what information should it contribute?

Queries and keys handle the first question. Values handle the second.

7. Query: what kind of relationship are we looking for?

To make the math concrete, imagine a simple made-up attention behavior involving this group of words:

fluffy   blue   creature   ...   forest

Suppose we want the noun creature to gather information from adjectives describing it.

We can imagine its query representing something like:

For this example: “Is there an adjective before me that should change my meaning?”

The query vector is produced by multiplying the token's embedding by a learned matrix.

q = WQE
What is WQ?

A matrix full of learned parameters. It is the same basic idea as the weight matrices from Chapter 1. Training decides what useful transformation this matrix should learn.

The query vector is smaller than the full embedding vector. Every token gets its own query by applying the same query matrix to its current embedding.

Important: the adjective question is only a clean teaching example of something the matrix operations could implement. Real learned attention heads are usually harder to interpret.

8. Key: a potential answer to a query

At the same time, another learned matrix creates a key for every token.

k = WKE

The query and key vectors live in the same smaller vector space, so they can be compared.

How should I think about a key?

As a potential answer to a query. If a key lines up strongly with a query, that token is a good candidate to be relevant to the token making the query.

In our adjective–noun example:

  • the query produced by creature is looking for the kind of relationship we care about;
  • the keys produced by fluffy and blue can align strongly with that query;
  • an unrelated token's key would align weakly or negatively.
QUERYWhat relation am I looking for?
KEYAm I a good match for that query?
VALUEIf I matter, what change should I contribute?

9. Query × Key gives us the attention pattern

To compare one query with one key, we take their dot product.

score = k · q

A larger positive dot product means stronger alignment. Do this for every key–query pair and we get a whole grid of scores.

Are those raw scores already attention weights?

Not yet. Raw dot products can be negative, bigger than 1, and they do not add up to 1. We first normalize each column with softmax.

Softmax turns a group of arbitrary numbers into positive weights that add up to 1. After softmax, the grid is called the attention pattern.

The adjective keys are aligned most strongly with the creature query, so they receive most of the weight.

With token vectors written as columns, the compact score-grid expression is:

softmax(KTQ / √dk)

The division by √dk keeps the dot-product values from becoming too large as the query/key dimension grows.

Why might I see QKT in another explanation?

It is a notation choice. If token vectors are stored as rows instead of columns, the same grid is written with the multiplication reversed. The underlying pairwise dot products are the same.

10. GPT adds one more rule: later tokens cannot influence earlier tokens

A GPT-style model predicts what comes next. During training, it can make predictions for many positions in the text at the same time.

That creates an important rule:

An earlier position must not get information from a token that appears later in the text.

Otherwise the model could “peek” at the answer it is supposed to predict.

So before softmax, all forbidden later-to-earlier scores are replaced by negative infinity. Softmax then turns those positions into exact zeros.

✓−∞−∞−∞ ✓✓−∞−∞ ✓✓✓−∞ ✓✓✓✓

This is called masking, or more specifically a causal mask.

Why does attention become expensive for long contexts?

The attention pattern has one row and one column for every token. If the context length doubles, the number of pairwise positions grows roughly with the square of the context length.

11. Values answer the second question: what information should move?

Queries and keys told us which tokens are relevant. But we still need to know what a relevant token should actually contribute.

A third learned matrix produces a value vector for each token.

v = WVE

For the simple adjective–noun picture, the value produced from fluffy can be thought of as a proposed change that would move another embedding toward a meaning that includes “fluffy.” The value from blue can propose a different change.

So is the Value just “the meaning of the word”?

Not exactly. In this picture, the value is better thought of as the adjustment that should be added if this token is relevant.

The attention weights tell us how much of each value vector to use.

ΔEtarget = Σ (attention weight × value vector)
E′ = E + ΔE

So the attention head does two jobs:

1

Q + K: decide what is relevant.

2

softmax: turn relevance into weights.

3

V: create possible updates.

4

weighted sum: add the right update to each embedding.

Check: Query, Key and Value in one sentence each

Query: the kind of relationship a token is looking for in this attention head. Key: a potential match to that query. Value: the change that token can contribute if it receives attention.

12. One attention head is not enough

The adjective–noun behavior is only one possible kind of contextual update. Language contains many different relationships.

So a full attention block runs many attention heads in parallel.

head 1its own Q, K, V maps
head 2its own Q, K, V maps
head 3its own Q, K, V maps
...many learned patterns

Each head proposes a change to each token embedding. Those proposed changes are combined and added back to the original embedding.

Using GPT-3 as the running scale example:

  • each transformer layer has 96 attention heads;
  • the model has 96 transformer layers;
  • the attention parameters across those layers account for just under 58 billion parameters.
Do we program one head to do adjectives, another to do pronouns, and so on?

No. The clean adjective example is only a way to understand what the computation could represent. The actual maps are learned from data, and their behavior can be much more complicated.

13. Attention is only half of the repeated transformer block

After an attention block, every token vector passes through a multilayer perceptron, or MLP.

This is the part that should feel very familiar from Chapter 1.

embedding E→large matrix + bias→ReLU / GELU-like nonlinearity→large matrix + bias→update

The same MLP operation is applied to every token vector independently and in parallel. During this step, the vectors do not exchange information with each other.

A made-up example to understand the MLP math

Imagine we want to understand how an MLP could encode an association between Michael Jordan and basketball.

This is a teaching construction, not a claim that a real model has one clean “Michael Jordan neuron.” Real models are much harder to interpret.

Suppose an earlier attention block has already produced a vector that contains information about both the first name Michael and the last name Jordan.

The first MLP matrix can be viewed row by row. Each row takes a dot product with the incoming vector. One row could act like a detector for the combination of those two features.

Add a bias of −1, then pass the result through ReLU:

ReLU( Michael-score + Jordan-score − 1 )

If both scores are present, the result can be positive. If only one is present, the result becomes zero after ReLU. In this simplified picture, that behaves like an AND gate.

Both features are present, so the neuron is active. The down-projection can now add a basketball-related direction.

Then the second matrix projects the large intermediate vector back down to the embedding dimension. It is useful to think of its columns as directions that can be added to the result when the corresponding neuron is active.

In the simplified example, the active neuron could cause a basketball direction to be added. The same column could also carry other associated information. Again, this is a conceptual example of what the matrices could do, not a literal map of one fact to one neuron in real models.

Using GPT-3's dimensions, one MLP expands the 12,288-dimensional embedding to just under 50,000 neuron activations, then projects back down. The two big matrices together contain about 1.2 billion parameters per MLP block. Across 96 layers, MLPs account for about 116 billion parameters — roughly two-thirds of the model's 175 billion parameters.

Connection back to Chapter 1: an MLP is still “matrix multiplication → bias → nonlinear activation → matrix multiplication.” The same neural-network building blocks are still inside the transformer.

14. How does the final vector become a next-token prediction?

After many alternating attention and MLP blocks, the final vector at the last position is supposed to contain the information needed to predict what comes next.

One more learned matrix, called the unembedding matrix, maps that vector to one raw score for every token in the vocabulary.

logits = WUElast
What is a logit?

A raw, unnormalized score. Logits do not need to be between 0 and 1, and they do not need to add up to 1.

Softmax converts those logits into a probability distribution:

probabilities = softmax(logits)

The model can then sample one token from that distribution, append it to the text, run the process again, and predict another token.

current text→transformer→next-token distribution→sample one token↺
Why doesn't the model simply choose the biggest probability every time?

It can, but language generation often samples from the distribution. A temperature setting can make the distribution flatter or sharper before sampling, which changes how much lower-probability options can be chosen.

15. Put the entire transformer together

We can now read the whole path without treating any step as magic.

01Tokenize

Break text into tokens.

02Embed

Map each token to a high-dimensional vector and include position information.

03Attention

Use Q and K to decide relevance; use V to create context updates.

04MLP

Process each contextual vector through a small neural network.

05Repeat

Alternate attention and MLP blocks through many layers.

06Unembed

Turn the final vector into one logit per vocabulary token.

07Softmax

Turn logits into next-token probabilities.

08Sample

Choose a token, append it, and repeat.

Transformer checkpoint: what should I be able to say now?

A transformer is a neural network that repeatedly alternates attention and MLP blocks. Tokens begin as embeddings. Attention uses learned query and key maps to decide which positions are relevant, then value maps produce updates that are mixed using attention weights. GPT also masks future positions. Multiple attention heads run in parallel. MLPs independently transform each token vector. After many layers, an unembedding matrix and softmax produce a probability distribution for the next token.

Now look at the math we have accumulated:

embedding lookup
WQ × embedding
WK × embedding
WV × embedding
key-query dot products
weighted value sums
MLP matrix multiplication
another MLP matrix multiplication
unembedding matrix multiplication

... repeated across many tokens and many layers
What kind of computer can do all of those matrix operations fast enough?

That is no longer only a neural-network question. It is a hardware question.
