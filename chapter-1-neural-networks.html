Chapter 1 · Foundations

Neural Networks, from zero.

We will start with one number going into one neuron and end with a complete training loop. Every new idea appears only because the previous idea creates a problem we need to solve.

Absolute beginner~30–35 min read3 interactive demosNo ML assumed

When someone says “the neural network learns,” what actually changes? Where are the rules stored? Who tells a weight whether to go up or down? This chapter is built around those exact questions.

examples→neuron→prediction→loss→gradient→update

1. Why do we need machine learning at all?

In normal programming, we know the rule, so we write the rule.

if temperature > 100:
    show_warning()

The computer does not discover anything. It follows the instructions we gave it.

Now imagine that we want a program that looks at a photo and tells us whether it contains a cat.

Why not just write the rules for “cat”?

Because the computer receives pixel values, not concepts such as “ears,” “fur,” or “cat.” A cat can appear at different angles, sizes, lighting conditions and backgrounds. Writing enough exact rules is not practical.

Machine learning changes what we give the computer.

Normal programmingRules + data → answer
Machine learningExamples + answers → learned rule

Instead of writing the full rule ourselves, we build a function with adjustable numbers inside it. We show it many examples. Then we keep adjusting those numbers until the function gives better answers.

The entire chapter in one sentence: a neural network is a function with adjustable parameters, and training is the process of finding parameter values that make its predictions better.

2. Five words before we build anything

These words appear everywhere in machine learning. It is much easier if we make them concrete now.

Feature

An input the model receives. Example: hours studied.

x
Label

The correct answer we want the model to learn. Example: pass or fail.

y
Prediction

The answer the model currently gives.

ŷ
Parameter

A number learned during training. Weights and biases are parameters.

w, b
Hyperparameter

A training choice we set, such as learning rate or batch size.

η
Model

The whole function that turns inputs into a prediction.

f(x; θ)
What is θ?

θ (“theta”) is often used as one symbol meaning “all the parameters in the model.” Instead of writing every weight and every bias, we can say the model has parameters θ.

3. What exactly is one artificial neuron?

Forget the brain analogy for a moment. An artificial neuron is just a small mathematical function.

Suppose we are building a tiny model that estimates whether a student is likely to pass. We give it three numbers:

x₁ = hours studied
x₂ = attendance
x₃ = previous score

The neuron receives those three inputs and returns one output.

Does the neuron understand “studying” or “attendance”?

No. It only receives numbers. Meaning comes from what those numbers represent in our dataset and from patterns the network learns.

4. Weights and bias: what do these numbers actually do?

The three inputs probably should not matter equally. Maybe hours studied matters a lot. Maybe attendance matters somewhat less. We give each input its own weight.

z = w₁x₁ + w₂x₂ + w₃x₃ + b

Read the equation from left to right:

1

Take an input x.

2

Multiply it by its weight w.

3

Add all the weighted inputs.

4

Add the bias b.

What does a weight mean?

A weight controls how strongly an input pushes the neuron's result and in which direction.

  • Large positive weight: this input strongly pushes the result upward.
  • Large negative weight: this input strongly pushes the result downward.
  • Weight near zero: this input has little effect.

Then what is the bias?

The bias is another learned number, but it is not attached to a particular input. It shifts the whole result.

Mental model: weights answer “how much should I care about each piece of evidence?” Bias answers “where should my default starting point be?”
Are weights and biases chosen by the programmer?

We usually initialize them, often with small random values. Training then changes them. The final useful values are learned from data.

When we write the same idea compactly, we collect all weights into a vector w and all inputs into a vector x:

z = wᵀx + b

The expression wᵀx is a dot product. In plain English, it means exactly what we already did: multiply matching entries and add the results.

5. Why do we need an activation function?

Right now our neuron computes a weighted sum. You might reasonably ask: if one weighted sum is useful, why not stack many of them?

Wouldn't many linear layers automatically become powerful?

No. Without a nonlinear step between them, many linear layers can still collapse into one linear transformation. More layers would look deeper, but they would not gain the ability to model truly curved, complicated relationships.

For a one-dimensional example:

y = w₁x + b₁

z = w₂y + b₂

Substitute the first into the second:

z = w₂(w₁x + b₁) + b₂ = (w₂w₁)x + (w₂b₁ + b₂)

After simplifying, it is still in the same straight-line form: some weight × x + some bias.

We need a bend. That bend is the activation function.

a = activation(z)

Sigmoid

Sigmoid squeezes any input into a value between 0 and 1. It is useful when the output should behave like a probability.

sigmoid(z) = 1 / (1 + e−z)

ReLU

ReLU is much simpler:

ReLU(z) = max(0, z)

Negative input? Output 0. Positive input? Keep it. ReLU became popular in deep hidden layers partly because its positive side does not flatten out like sigmoid's tails.

Check: what is the difference between z and a?

z is the weighted sum before the activation. a is the neuron's output after the activation function has been applied.

6. How does one neuron become a layer?

One neuron gives one output. A layer contains many neurons looking at the same input. Each neuron has its own weights and bias, so each can learn a different pattern.

One layer = many neurons in parallel

Writing every neuron's equation one by one would be messy. So we stack the neurons' weights into a matrix W, and their biases into a vector b.

z = Wx + b     →     a = activation(z)
Is that a new idea?

No. It is the exact same neuron equation, just performed for many neurons at once. Each row of W holds one neuron's weights.

This matrix form will matter again in the hardware chapter, because modern AI spends enormous amounts of time doing matrix multiplication.

What are hidden layers learning?

A hidden layer is not given a human-written meaning. Its job is to create internal features that make the final prediction easier.

For an image, you can imagine a rough progression:

pixels→edges→shapes→parts→object

This is only an intuition, not a promise that every neuron cleanly maps to a human concept. The important idea is that later layers can build on patterns created by earlier layers.

7. What is a forward pass?

Once the network has weights and biases, we can use it to make a prediction.

We start with the input, run the first layer, take its output into the next layer, and continue until we reach the final output.

input x
  ↓
layer 1: z¹ = W¹x + b¹  →  a¹ = activation(z¹)
  ↓
layer 2: z² = W²a¹ + b² →  a² = activation(z²)
  ↓
output: ŷ

This movement from input to prediction is called the forward pass.

Does the model learn during the forward pass?

Not yet. The forward pass only uses the current parameters to produce a prediction. To learn, we must first measure how wrong that prediction is.

8. Loss: how does the network know it was wrong?

Suppose the correct answer is 7, but the network predicts 2. Saying “wrong” is not enough. Training needs a number that says how wrong.

That number is the loss.

small loss
good prediction
large loss
bad prediction

A simple regression loss: squared error

If we are predicting a number, a simple loss is:

L = (ŷ − y)²

If the prediction is 9 and the correct answer is 10, the error is −1 and the squared loss is 1. If the prediction is 2 and the answer is 10, the error is −8 and the squared loss is 64. Big misses are punished more strongly.

Classification uses a different idea

For categories, the network often outputs probabilities. A common loss called cross-entropy gives a small penalty when the correct class receives high probability and a large penalty when the model is confidently wrong.

Do not get stuck on the formula yet. The core job of any loss is the same: convert prediction quality into one number we can try to reduce.
So learning means minimizing loss?

Yes. More precisely, training tries to find weights and biases that produce a low average loss across the training examples.

9. From derivative to gradient: how do we know what to change?

Now we have millions of parameters and one loss number.

If the loss is 4.7, what does that tell weight #183,421 to do?

Nothing by itself. We need to know how the loss would change if we nudged each parameter. That is where derivatives and gradients enter.

Derivative = one slope

Imagine the loss depends on only one weight, w. A derivative tells us the slope of the loss curve at our current value of w.

positive derivativemove w right → loss rises
negative derivativemove w right → loss falls
near zerothe curve is locally flat

Partial derivative = one slope while other parameters stay fixed

A real loss depends on many parameters. So we ask the same slope question one parameter at a time.

∂L / ∂w₁    ∂L / ∂w₂    ∂L / ∂b₁    …

Gradient = all those slopes together

The gradient is simply the collection of all those partial derivatives. Think of it as one giant arrow telling us the direction in parameter space where loss increases fastest.

So to reduce loss: move in the opposite direction of the gradient.

10. Gradient descent: the actual update rule

Imagine standing on a mountain in fog. You cannot see the entire landscape. But you can feel the local slope under your feet. If you want to go downhill, step opposite the uphill direction.

θnew = θold − η ∇L

The pieces:

  • θ: all model parameters.
  • ∇L: the gradient, the uphill direction.
  • −: flip uphill into downhill.
  • η: the learning rate, which controls step size.
What if the learning rate is too small?

Training can move painfully slowly.

What if it is too large?

The updates can jump over good values, bounce around, or even diverge.

Does gradient descent calculate the gradient?

No. Gradient descent tells us what to do after we know the gradient. We still need an efficient way to calculate all those derivatives in a large network.

11. Backpropagation: how do we calculate all the gradients?

This distinction is worth repeating:

BACKPROPAGATIONcalculates the gradients

“How did each parameter affect the final loss?”

GRADIENT DESCENTuses the gradients

“Now update each parameter in the downhill direction.”

Backpropagation works because a neural network is a chain of computations. One value affects another, which affects another, which eventually affects the loss.

The chain rule in plain English

Suppose:

x changes u
u changes y

Then to know how much x affects y, we combine the two local effects.

effect of x on y = (effect of x on u) × (effect of u on y)

That is the intuition behind the chain rule.

Why move backward?

During the forward pass we already computed and stored intermediate values. Once we know how the final output affected the loss, we can move backward and reuse that information layer by layer.

input→layer 1→layer 2→prediction→loss
forward pass: compute and remember values
gradients←weights 1←weights 2←output error←loss
backward pass: pass sensitivity backward

The crucial idea is reuse. Backprop does not independently recompute the entire network once for every single parameter. It systematically shares intermediate derivative calculations, which makes training large networks practical.

When people say “the error moves backward,” is the original prediction literally traveling backward?

No. What moves backward is derivative information: how sensitive the final loss is to earlier values and parameters.

Check: backpropagation vs gradient descent

Backpropagation efficiently computes derivatives of the loss with respect to parameters. Gradient descent uses those derivatives to decide how to change the parameters.

12. What does training look like in practice?

So far we imagined one example. Real training uses many examples.

Batch

A batch is a group of training examples processed together. Instead of updating the model after one example or waiting for the entire dataset, we commonly use manageable mini-batches.

Step / iteration

One training step usually means: take one batch, run the forward pass, calculate loss, backpropagate, then update the parameters.

Epoch

One epoch means the training process has gone through the entire training dataset once.

batcha chunk of examples
→
stepone update using a batch
→
epochone full pass through the dataset

Why don't we only care about training loss?

A model can become very good at the examples it has already seen and still perform badly on new examples. That is overfitting.

So datasets are commonly separated:

Training setlearn parameters
Validation settune choices
Test setfinal evaluation

The real goal is not memorizing training data. It is generalization: performing well on useful new examples.

13. Put everything together: what does “the network learns” actually mean?

01Take a batch

Examples enter the network as numbers.

02Forward pass

Current weights and biases produce predictions.

03Calculate loss

Measure how wrong the predictions are.

04Backpropagate

Calculate how each parameter affected that loss.

05Update

Gradient descent changes parameters a little.

06Repeat

Many steps gradually produce more useful parameters.

Nothing inside this loop requires the model to “understand” its mistake the way a human does. The process is numerical:

prediction → loss → derivatives → parameter update

Yet when this process is repeated over large datasets with powerful architectures, the learned parameters can represent extremely complicated patterns.
